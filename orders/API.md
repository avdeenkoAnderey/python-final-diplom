# API дипломного проекта — этап 4

Запускайте команды из папки `orders` при активированном окружении `.venv`.

```powershell
python manage.py migrate
python manage.py runserver
```

Базовый адрес: `http://127.0.0.1:8000/api/v1/`. Маршруты принимают адреса с завершающим `/` и без него.
Защищённые методы требуют заголовок `Authorization: Token <токен из ответа входа>`.

## Каталог и аккаунт

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | categories | Категории |
| GET | shops | Магазины, принимающие заказы |
| GET | products | Предложения; фильтры `shop_id`, `category_id`, поиск `search` |
| GET | products/ID | Отдельное предложение |
| POST | user/register | Регистрация покупателя |
| POST | user/register/confirm | Подтверждение email: `email`, `token` |
| POST | user/login | Вход: `email`, `password` |
| GET | user/details | Свой профиль |
| PATCH, POST | user/details | Изменение имени, фамилии, компании, должности |
| POST | user/password_reset | Запрос письма: `email` |
| POST | user/password_reset/confirm | Сброс пароля: `uid`, `token`, `password` |

Для регистрации нужны `email`, `password`, `first_name`, `last_name`; компания и должность необязательны.
До подтверждения email новый покупатель не может войти. При сбросе пароля старые токены входа удаляются.
Срок действия токена восстановления определяется стандартной настройкой Django `PASSWORD_RESET_TIMEOUT`.

## Контакты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET, POST | user/contact | Свои адреса / создание адреса |
| GET, PATCH, PUT, DELETE | user/contact/ID | Просмотр, изменение, удаление своего адреса |

Обязательные поля адреса: `city`, `street`, `house`, `phone`.
Необязательные: `structure`, `building`, `apartment`.
Владелец назначается по токену; чужой адрес возвращает 404. Использованный в заказе адрес удалить нельзя (400).

## Корзина и заказы

| Метод | Путь | Данные / назначение |
| --- | --- | --- |
| GET | basket | Своя корзина; пустая корзина имеет `id: null` |
| POST | basket | `{"product_info": 1, "quantity": 2}` — добавление количества к позиции |
| PATCH | basket/ID_ПОЗИЦИИ | `{"quantity": 3}` — установить количество |
| DELETE | basket/ID_ПОЗИЦИИ | Удалить позицию корзины |
| POST | order | `{"id": 1, "contact": 1}` — оформить свою корзину со своим адресом |
| GET | order | История своих оформленных заказов |
| GET | order/ID | Детали своего заказа |
| PATCH | order/ID/status | Только администратор: `{"state": "confirmed"}` |

Корзина доступна покупателям. `product_info` — ID предложения магазина, а не ID товара.
При оформлении повторно проверяются доступность магазина и остатки, списание выполняется атомарно.
Цена фиксируется по текущему прайсу в момент оформления и впоследствии не меняется при обновлении каталога.
Уже оформленную корзину повторно отправить нельзя. Количество должно быть больше нуля.

Статусы: `new → confirmed → assembled → sent → delivered`.
Из `new`, `confirmed`, `assembled` администратор может перевести заказ в `canceled`; остатки возвращаются один раз.
Статус всего заказа меняет администратор, а не отдельный поставщик многомагазинного заказа.

### Пример PowerShell

```powershell
$token = Read-Host "Вставь токен покупателя"
$headers = @{ Authorization = "Token $token" }

$basket = Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/basket" -Method Post -Headers $headers -ContentType "application/json" -Body '{"product_info":1,"quantity":2}'

$body = @{ id = $basket.id; contact = 1 } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/order" -Method Post -Headers $headers -ContentType "application/json" -Body $body

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/order" -Headers $headers
```

Подставьте существующие ID предложения и своего адреса. Сервер должен быть запущен в другом терминале.

## Поставщик

Пользователя с типом `shop` создаёт администратор. Затем поставщик входит через `user/login`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | partner/update | Загрузка YAML-прайса: multipart/form-data, поле `file` |
| GET | partner/state | Состояние своего магазина |
| POST, PATCH | partner/state | `{"state": false}` — отключить приём заказов |
| GET | partner/orders | Заказы с товарами своего магазина |

Загрузка прайса принимает файл до 2 МБ в формате `data/shop1.yaml`. Например:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/api/v1/partner/update" -H "Authorization: Token $token" -F "file=@../data/shop1.yaml"
```

Здесь `$token` должен принадлежать поставщику. Импорт по URL не используется: файл передаётся непосредственно в API.
Повторная загрузка обновляет предложения, не удаляя историю заказов. Отсутствующим в файле предложениям назначается
нулевой остаток; отсутствующие характеристики удаляются. Некорректный каталог отклоняется целиком.
Для текущего учебного формата ID категорий считаются общими для сервиса.

Поставщик получает только свои позиции и их сумму, даже если заказ содержит товары других магазинов.

## Письма и проверки

В разработке используется консольный почтовый backend: письма видны в терминале сервера.
Для накладных используется демонстрационный получатель `admin@example.com`.
Реальная отправка SMTP не настроена; сформированные письма выводятся в терминал.

После фиксации заказа покупателю отправляется подтверждение, администратору — накладная с позициями,
ценами, количеством, адресом и итогом. Изменение статуса через API также отправляет уведомления.
Сбой отправки не отменяет уже сохранённый заказ; он журналируется Django. Очередь и повторная доставка
писем относятся к последующему расширению с Celery.

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test backend --noinput
```

Тесты создают отдельную SQLite-базу Django и не меняют рабочую `db.sqlite3`.
